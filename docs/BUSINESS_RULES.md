# BUSINESS_RULES — SEPahan Academy OS

> وضعیت: هیچ‌یک هنوز پیاده‌سازی نشده. این سند قرارداد رفتاری فازهای بعد است.

## 1. هویت افراد

1. `Person.nationalCode` یکتاست.
2. اگر فردی برای Tryout ثبت‌نام کند و از قبل `Player` داشته باشد، **همان رکورد استفاده می‌شود**. ساخت Player تکراری ممنوع است.
3. `Player.playerCode` یکتاست.

## 2. مسیر ورود بازیکن

سه مسیر معتبر:

| مسیر | جریان |
|---|---|
| A | School → Tryout → Accepted → Main Team |
| B | Tryout مستقیم → Accepted → Main Team |
| C | School → تصمیم مدیر → Main Team |

**قاعده حساس:** پذیرش بازیکن در تیم اصلی، `SchoolEnrollment` او را به‌صورت خودکار حذف یا باطل **نمی‌کند**. تغییر وضعیت ثبت‌نام مدرسه فقط با اقدام صریح مدیر انجام می‌شود.

دلیل: بازیکن ممکن است هم‌زمان در مدرسه بماند؛ حذف خودکار، داده تاریخی را از بین می‌برد.

## 3. پذیرش Tryout — Transaction

پذیرش یک درخواست باید **اتمیک** باشد:

```
Application → ACCEPTED
   ↓
TeamMembership ساخته/فعال می‌شود
   ↓
PlayerJourneyEvent ثبت می‌شود
   ↓
Notification ارسال می‌شود
```

اگر هر مرحله شکست بخورد، کل Transaction Rollback می‌شود. وضعیت نیمه‌کاره (درخواست پذیرفته‌شده بدون عضویت تیم) مجاز نیست.

## 4. رده سنی

Age Group هنگام Tryout و Enrollment اعتبارسنجی می‌شود. Admin می‌تواند استثنا ثبت کند، اما استثنا باید Audit شود.

> **باز — نیازمند تصمیم:** مبنای محاسبه رده سنی هنوز مشخص نیست: سال تولد یا تاریخ دقیق؟ مبدأ، شروع فصل ورزشی است یا تاریخ ثبت‌نام؟ این تصمیم قبل از Phase 6 لازم است.

## 5. کادر فنی

Staff فقط تیم‌هایی را می‌بیند و مدیریت می‌کند که از طریق `StaffTeam` به او Assign شده‌اند.

## 6. داده تاریخی

رکوردهای تاریخی Hard Delete نمی‌شوند. به‌جای حذف، از وضعیت استفاده می‌شود:

| موجودیت | به‌جای حذف |
|---|---|
| SchoolEnrollment | `TRANSFERRED` / `COMPLETED` / `CANCELLED` |
| TeamMembership | `INACTIVE` / `RELEASED` |
| Player | `INACTIVE` / `TRANSFERRED` / `RETIRED` |

## 7. حضور و غیاب

مربی ابتدا «همه حاضر» را می‌زند و سپس موارد استثنا را اصلاح می‌کند:
`PRESENT` · `LATE` · `ABSENT` · `EXCUSED`

هر جلسه تمرین برای هر بازیکن فقط یک رکورد حضور دارد.

## 8. ارزیابی

`EvaluationTemplate` قابل تنظیم است. ابعاد پیش‌فرض: Technical، Physical، Mental، Overall.
هر معیار در هر ارزیابی فقط یک امتیاز دارد.

## 9. Audit

این عملیات همیشه Audit می‌شوند: تغییر نقش، تغییر وضعیت بازیکن، عضویت تیم، تصمیم Tryout، ارزیابی، تغییرات مهم پروفایل، عملیات اسناد، رویدادهای امنیتی.
