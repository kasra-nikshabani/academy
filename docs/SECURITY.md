## 2. Redaction لاگ‌ها

قانون در `lib/logger/redact.ts` و نه در محل فراخوانی enforce می‌شود؛ بنابراین حتی یک `logger.info("...", { otp })` بی‌احتیاط هم نشتی ایجاد نمی‌کند.

| نوع داده | رفتار |
|---|---|
| OTP، Token، Password، Secret، API Key، Authorization، Cookie، DATABASE_URL | کامل حذف → `[REDACTED]` |
| کد ملی | فقط طول باقی می‌ماند → `[NATIONAL_ID:10]` |
| شماره موبایل | ماسک جزئی → `0912***6789` |

ماسک جزئی موبایل عمدی است: پشتیبانی باید بتواند گزارش کاربر را دنبال کند بدون اینکه شماره کامل در لاگ بماند.

عمق پیمایش محدود است تا ساختار بازگشتی باعث توقف سرویس نشود.

تست‌ها: `tests/unit/redact.test.ts`

## 4. قواعدی که در فازهای بعد اجرا می‌شوند

### OTP (Phase 2)
- کد به‌صورت Hash ذخیره می‌شود، نه Plaintext
- انقضای کوتاه (پیش‌فرض ۱۲۰ ثانیه)
- مصرف یک‌باره؛ کد استفاده‌شده قابل Replay نیست
- سقف تلاش و Cooldown برای ارسال مجدد
- کد هرگز در پاسخ API برنمی‌گردد و هرگز لاگ نمی‌شود
- مسیر خطا نباید تفاوت «شماره ناشناس» و «کد اشتباه» را لو بدهد

### Authorization (Phase 3)
- هر Endpoint دو بررسی جدا دارد: **Permission** و **Scope**
- مخفی‌کردن دکمه در UI هرگز به‌عنوان کنترل امنیتی حساب نمی‌شود
- تغییر ID در URL نباید به داده شخص دیگری برسد — این سناریو تست E2E اجباری دارد

### Upload (Phase 18)
- محدودیت نوع فایل و حجم
- نام فایل کاربر هرگز مستقیم روی دیسک استفاده نمی‌شود
- فایل‌ها خارج از مسیرهای اجرایی ذخیره می‌شوند

### Audit (Phase 19)
عملیات حساس ثبت می‌شوند: تغییر نقش، تغییر وضعیت بازیکن، عضویت تیم، تصمیم Tryout، ارزیابی، تغییرات مهم پروفایل، عملیات اسناد و رویدادهای امنیتی.
